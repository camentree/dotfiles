# The work page's data

Camen's work page shows every piece of work by whose hands it is in. Three writers, three places, joined by the server. Nobody writes another's file.

| Writer | File | Holds |
|---|---|---|
| `~/.claude/scripts/work-state.cjs`, run by the server every 2 minutes while the page is polled or an agent works (see Syncing with GitHub) | `~/Documents/notes/work/github.json` | Facts from GitHub: his open pull requests, and in `teammates` every open pull request by someone else (in valinor, august-backend, august-frontend, Experimental-Tools) that asks for his review by name or through the move-ins team, that he has reviewed, or that a `kind: teammate` task points at (he works only on move-ins: a request through any other team, such as integrations, is left out, 2026-11-24). Drafts are not listed until they are ready for review, as his find-reviews rules always had it (only a draft an agent's task points at shows). Each teammate entry carries `needsMe` and `why` (his rules, from `review-queue.cjs`), `reason` (`asks you`, `asks <team>`, `watched`), `requestedMe`, `teamsPending`, `othersPending`, `labels`, `draft`, `myReview` (`{ state, at }`), `pendingReview` (he has an unsubmitted review open), `reviewDecision`. Every pull request, his and teammates', carries `reviewedBy` `{ people, bots }`: the logins other than the author who left a review or a comment in an open thread, split by GitHub's `Bot` type (`greptile-apps` is one); a carried-over "**<login>** wrote on the old pull request" comment counts as that login's. His `reviewCount` leaves bots out (greptile's review used to read "1 review"). A refresh that fails anywhere writes nothing, so the last good file stays. Never edited by hand or by an agent. |
| The agent working on a task, through `~/.claude/scripts/task-set.cjs` | `~/.claude/tasks/<repo>/<branch>/task.json` | What the agent knows: explanation, decisions, proof, findings, a question, its own status, the drafted description. |
| `~/.claude/scripts/work-server.cjs`, port 4990 | `~/Documents/notes/work/mine.json`, `projects.json`, `log.jsonl`, `outbox.jsonl`, `answers.jsonl`, `placement.json`, `departed.json`, `syncs.jsonl`, `moves.jsonl` | What he did on the page: ticks, the Day, asked marks, snoozes, dismissals, order, tasks he added, Log messages, messages waiting for a busy session, and every answer he gave an agent. Also the order of every section and group and the day's trace rows (`placement.json`), what became of pull requests that left GitHub's lists today (`departed.json`: merged by whom, closed, or still open), and the last 50 syncs with GitHub (`syncs.jsonl`). Agents change these only through the server's API. |

The page is `~/.claude/skills/assistant/page/index.html`, served by the server at `http://localhost:4990`. Every "#<number>" it draws from text (facts, standings, Blocked reasons, agent lines, explanations, decisions, questions, sync history, the Log in the + chat) becomes a link through one helper: hover shows the card's title, whose, section → group, standing and checks; a click goes to the card when it is on the Status tab, else opens the pull request on GitHub (in the card's repository, valinor when there is none); cmd/ctrl-click always opens GitHub; inside a ghost it is inert. So write pull requests as "#87" in anything the page shows. Beside it, `review.html?id=<card id>&port=<difit port>` frames a difit server under a thin bar holding one button, "agent" (opens the card's agent session in Ghostty through `POST /api/terminal { id }`, on the machine the server runs on, which its tooltip names when the wrapper was opened from another device; disabled when the card has no agent session; "opened ✓" or a red "not opened · retry"). Its send comments button was removed 2026-11-25: presses passed on through the assistant were refused by the permission check whenever they led to a push or post, so the agent now picks up each comment itself with the difit comment monitor it arms on `[reviewing]`; the tab is titled `(difit) <card title>`; publish stays on the card; one wrapper per difit server, no switch, and a `(difit LAN)` tab entry, being the same server, never adds a link; `buttons.js` holds each button's label, tooltip and the reason it is unavailable, shared by both pages. A card's `difit` link on the page opens that wrapper, not the bare difit url. `~/Documents/notes/work/config.json` holds switches (`{ "autostart": false, "maxAutoAgents": 3, "assistant": true }`). Autostart, after each sync, starts an address or fix agent on his pull request with open threads waiting on him (the `threadWaitsOn` rule), failing checks or a conflict, once per head and thread count (`mine.autostarted`), never on one he has ticked or completed: the sync's state build first clears a mark when something new came after it (the tick-clearing events), so a mark still standing means nothing new (#87 restarted on a thread he had settled, 2026-11-25).

## The task and its flow (2026-11-25 redesign)

The page is built around one flow: agents prepare things for his review, they land in **Queued**; he presses **review** and it is **In Progress** (only ever: he is reviewing it now, never "an agent is working"); from there he queues it again, blocks it, or ticks it done. Every card, wherever it shows, is one Task component with these fields:

| Field | What it is | Who writes it |
|---|---|---|
| `state` | `not-started`, `preparing` (an agent is working on it), `queued` (prepared for him), `in-progress` (he pressed review), `blocked` (he pressed block), `complete`. Computed by the server, first match: `complete` when the card sits in a Complete group; `blocked` when `mine.blocks[id]`; `in-progress` when `mine.flow[id].state` is `in-progress`; `preparing` when its agent is `working`; `queued` when `mine.flow[id].state` is `queued`, or it has `materials`, or its task has `ready`; else `not-started`. Reaching Complete clears `flow` and `blocks`. | server, from his presses (`mine.json` `flow`, `blocks`) and the agent's `task.json` |
| `materials` | `[{ kind, label, url }]`, kind `pr`, `difit`, `context`, `proof`, `linear` or `other`: every page review opens, in order. With no `materials` in `task.json`, while the agent is `ready`/`reviewing` or `ready` is set (and on any `queued` card), the server derives them from what the task has, in this order, same url once: every `review.tabs` url (a difit tab becomes its wrapper url), the wrapper url `http://localhost:4990/review.html?id=<card id>&port=<port>` of each `review.difit` entry with a `port` or `url`, the pull request, and proof pages (`kind` `page`, and `proof/index.html` when it exists). Before 2026-11-25 only `review.tabs` counted, so #102 (fixes ready, no `review`) sat in Queued with review disabled. | agent: `task-set.cjs --material "kind|label|url"`, `--material-clear` |
| `tabGroup` | Safari tab group name. Default `<author or project or "pr N"> - <first three title words>`, lowercase. | agent: `--tab-group` |
| `project`, `stackOrder` | Shown first on the title row ("Linked Residents", "2/4"); replaced the backend/frontend tags. Only `draft` remains as a tag. | `task.json` / projects, GitHub stack |
| `block` | `{ reason, at }` while blocked. | server, `POST /api/block` |
| `greptileReviews`, `teammateReviews` | Counts of Greptile and of people (not him, not the author) in `reviewedBy`; drawn as an icon and a number in the facts line. Replaced "N reviews" and the "greptile only" tag. | server |
| `checkFailed` | `{ reason, at }`: the assistant found a ticked task not done. Red border, "Not done: <reason>" on the card. A new tick or an untick clears it. | assistant, `POST /api/check-result` |

The card: tick, state pill (only where the view does not already say the state: Projects, not Status sections or Now), project, stack position, tags, title; top right the speech bubble, pencil, and a robot that opens the task's Claude session in Ghostty (`/api/terminal`); facts line without any status words; buttons `answer` and `merge` where they apply, then always `queue`, `review`, `block`, `to queue` (`requeue`), `dismiss` (snooze was removed 2026-11-25; `/api/snooze` and already-snoozed cards are left alone); one status line, not clickable: the agent's status, else the card's `standing`; then "Not done: …" and "Blocked: …" lines. No agent button, no note box, no Day "+", no grey ghost copies (traces are no longer kept).

- **queue**: starts the agent that prepares what he needs to review (teammate's: `review`; his with threads: `address`; failing checks or a conflict: `fix`; his otherwise: `review`; no pull request: `start`, or `review` when `ready` is set) with a note to record materials, and it shows `preparing` until the agent stops working. Disabled while queued, preparing or in progress, when materials are already prepared, and on his pull request whose only need is a teammate's review (`waitsOnTeammate`: Ask, or PRs → Waiting for Review; `/api/queue` refuses it too). It comes back once something returns to him and the card moves out of those.
- **review**: opens every `materials` url in one Safari tab group named `tabGroup` (`~/.claude/scripts/safari-tab-group.applescript`, the chrome-tab-groups skill's Safari recipe, under `/tmp/safari-tab-group.lock`; dry run logs it instead), sets In Progress, and sends a live agent `[reviewing]` so it starts the app and difit. Always enabled on a Queued card: one still without materials sends its agent `[open review]` (as `/api/open`) and sets In Progress. Disabled, with a tooltip, elsewhere without materials.
- **to queue** (`requeue`): moves an In Progress or Blocked card back to Queued, clearing the block, and sends a live agent `[paused]`. `POST /api/requeue { id }`, 409 in any other state.
- **dismiss**: hides the card for good; restored from the hidden list under the section.
- A card in a Complete group that got there by his tick, `/api/complete` or `/api/check-result` has `checked: true`, whatever section the tick was made in.
- **block**: an inline one-line box; sets `block`, adds "Blocked: <reason>" to his comments, sends the assistant `[blocked] <id> <reason>`.
- **tick**: stays ticked and sends the assistant `[checked] <id> <title> <card url and material urls>`. The assistant answers with `POST /api/check-result`. On an Ask card the tick still means "I asked".

`task-set.cjs` new flags: `--material "<kind>|<label>|<url>"` (repeatable; same url replaces), `--material-clear`, `--tab-group "<name>"`. A material counts as agent activity (sets `updated` and the heartbeat).

## `task.json`

One per task, beside `plan.md`, `proof/` and `review/` in the task directory. `<repo>` is the `basename` of `git remote get-url origin` without `.git`, `<branch>` is the branch, slashes kept as subdirectories. A teammate's pull request uses its head branch. A by-hand task has no file: it lives in `projects.json`, with its `explanation` there too, set through `POST /api/task-explanation`.

```json
{
  "id": "valinor/camen/mov-474-copy-facility",
  "title": "Copied contacts and documents in the CopyFacility job",
  "kind": "mine",
  "project": "Linked Residents",
  "repo": "valinor",
  "branch": "camen/mov-474-copy-facility",
  "base": "master",
  "worktree": "/Users/camen/Projects/.valinor-worktrees/camen/mov-474-copy-facility",
  "pull": null,
  "ticket": "https://linear.app/august-health/issue/MOV-474",
  "agent": {
    "session": "mov-474 - copy facility",
    "sessionId": "0d1d76aa-...",
    "state": "working",
    "doing": "building group 2 of 3",
    "since": "2026-11-23T13:05:00Z",
    "heartbeat": "2026-11-23T13:41:00Z"
  },
  "ready": null,
  "explanation": "Copying a facility makes a new facility from an old one. Until now the copy left out residents' contacts and uploaded documents. This adds both to the copy job.",
  "decisions": [
    { "title": "Copies documents in batches of 100", "why": "The job timed out copying 4,000 documents in one transaction.", "alternative": "One transaction for the whole facility" }
  ],
  "findings": [
    { "title": "Typed rate is lost when the assessment is redone", "detail": "Enter 4,200, redo the assessment, the field is empty.", "reproduced": true }
  ],
  "proof": [
    { "caption": "A 4,000-document facility copied end to end", "file": "proof/copy.mp4", "kind": "video" }
  ],
  "context": [
    { "caption": "The Copy facility screen on master", "file": "context/copy-screen.png", "kind": "image" }
  ],
  "question": null,
  "description": null,
  "labels": [],
  "review": null,
  "updated": "2026-11-23T13:41:00Z"
}
```

- `kind`: `mine` (his branch or pull request) or `teammate` (someone else's pull request he reviews).
- `pull`: the pull request url once there is one. The server joins `task.json` to `github.json` on it, else on `repo` + `branch`.
- `agent.state`: `working`, `blocked` (a question is open), `ready` (something waits for him, see `ready`), `reviewing` (his review is open in difit), `done`. The server shows `stopped` itself when `state` is `working` and the session is gone from `claude agents --json`, or `heartbeat` is older than 20 minutes while the session is no longer busy (a busy one may be sitting in a long `gh pr checks --watch`), or the session is waiting on an approval.
- `agent.kind`: `fix`, `address`, `review` or `start`, set by the server (`task-set.cjs --agent-kind`) when it starts the session through `POST /api/agent` or autostart, and dropped when a new `--session-id` arrives without one. While the agent is `working`, the card's status line leads with it: "fixing CI · reading logs", "addressing comments · …", "reviewing · …", "building · …" (2026-11-25). With no kind the page reads one from a `doing` that starts "fixing CI:", "addressing comments:", "reviewing:" or "building:" (or the old "<kind> starting"), and strips that prefix so it never shows twice.
- `agent.doing`: five words or fewer, no urls, no lists ("preparing the review", "waiting for publish"), since it shows at the top right of the closed card and he found every one too long (2026-11-24). Detail goes in a decision or the explanation.
- `agent.heartbeat`: set on every `task-set.cjs` call. A working agent calls it at least every 10 minutes, with `--doing` saying what it is on.
- `ready`: what waits for him. `review` (the agent's review of a teammate's pull request is prepared), `fixes` (review comments or CI are fixed and wait for his look before pushing), `work` (a built task, pushed, no pull request yet). `null` otherwise.
- `explanation`: two to four sentences for someone new to this part of the product. See `writing.md`.
- `decisions`: every choice the agent made without asking that he might want reversed.
- `findings`: an agent's review of the change, each run before it is written.
- `proof`: files relative to the task directory. The page shows them in order, one at a time. `kind` is `video`, `image` or `page`. Give the recordings and screenshots themselves first, each with its own caption, since he sees those without leaving the card; a proof page (`proof/index.html`, kind `page`) shows only as a link, so it goes last (the first prepared review recorded only the page, 2026-11-23).
- `context`: pictures that go with the explanation, taken on master before any work: where the feature will go, or what the bug is. Same shape as `proof`, files under `context/` (`context/<name>.png|mp4`), `kind` `image` or `video`. Proof shows finished work works; context shows what the work is about. Writing it, like writing an explanation, leaves the card without an agent.
- `question`: `pictures` may hold videos too (`.mp4`, `.mov`, `.webm`, `.m4v` by extension, else an image): the card's viewer plays them with controls, and the speech-bubble menu shows each picture (click to enlarge) and video inline, while the question is open or answered and not yet picked up. Shape: `{ "text", "explanation", "why", "options": [{ "label", "cost" }], "pictures": ["proof/q1.png"], "asked": "<iso>", "answer": null }`. `why` says why it could not be decided without him. The server fills `answer` (`{ "text", "options": ["<label>"], "at" }`) and delivers it to the agent's session. Clear it with `--question-clear` once acted on.
- `description`: the pull request description drafted for him to edit before publishing.
- `review`: for a prepared review, `{ "difit": { "base": "<sha>", "comments": "comments.json" }, "tabs": [{ "label": "(context)", "url": "..." }] }`: what opens when he presses review. `difit` is a list of those, each with its `target` and a `label` (three to five words on what that commit does), when the review has one server per commit (fixes to review comments). The card carries those labels as `difitLabels`, in the same order as its difit links. The wrapper's tab title is `<name> · <card title, shortened>`, the name from the url's `&name=`, else the `(difit <name>)` tab label for that port, else the matching `label`; with none, `difit 2 of 3 · <card title>` when the card has several servers, and `(difit) <card title>` for one. The card's difit links read `difit: <name>` and pass `&name=`.

## `task-set.cjs`

Run from the task's worktree (it works out `<repo>` and `<branch>`), or pass `--task <repo>/<branch>`. Creates the file when missing. A call that does agent work (`--state`, `--doing`, `--ready`, `--session`, `--session-id`, `--description-file`, a decision, a finding, proof, a question, `--review-file`, or any of the `-clear` flags but `--context-clear`) sets `updated` and `agent.heartbeat`, creating `agent` when missing. A call that only describes the task (`--explanation`, `--context`, `--context-clear`, `--title`, `--kind`, `--project`, `--pull`, `--ticket`, `--base`, `--label`) sets `described` instead and leaves `agent` and `updated` alone, so it never reads as an agent looking at the card; it also drops an `agent` that holds nothing but a heartbeat.

```bash
node ~/.claude/scripts/task-set.cjs \
  [--title "..."] [--kind mine|teammate] [--project "..."] [--pull <url>] [--ticket <url>] [--base <branch>] \
  [--state working|blocked|ready|reviewing|done] [--doing "..."] [--session "<name>"] [--session-id <uuid>] \
  [--ready review|fixes|work|none] \
  [--explanation "..."] [--description-file <path>] [--label <label>]... \
  [--decision "<title>" --why "..." [--alternative "..."]] \
  [--finding "<title>" --detail "..." [--reproduced]] \
  [--proof <file> --caption "..."] [--proof-clear] [--findings-clear] [--decisions-clear] \
  [--context <file> --caption "..."] [--context-clear] \
  [--question "<text>" --explanation-q "..." --why-q "..." --option "<label>|<cost>"... [--picture <file>]...] [--question-clear] \
  [--review-file <path to json>] \
  [--material "<pr|difit|context|proof|linear|other>|<label>|<url>"]... [--material-clear] [--tab-group "<name>"] \
  [--json]
```

`--json` prints the file. A question sets `state` to `blocked`; the agent then ends its turn. The answer arrives as a message in its session.

## Server API

All under `http://localhost:4990`. Bodies are JSON.

| Call | Does |
|---|---|
| `GET /api/state` | Everything the page draws (below). |
| `POST /api/tick` `{ id, checked }` | His tick on a card: "done with this for now". Stored in `mine.json` as `{ checked, section, at, checks, waits, agentState }` (when, and what the card looked like then). Cleared when the card changes section, and also, on any state build, when something put the card back in his hands after `at`: on a teammate's pull request the author responded after his last review (a commit, a thread comment, or his review requested again) or a prepared review became ready; on his own pull request a new review, a new comment by anyone else in an open thread, fixes ready for his look, checks going from passing to failing, or a blocked one becoming mergeable; on any card an agent asking a question or stopping (or needing an approval); on agent work without a pull request the work becoming ready. Nothing else clears it: not his own actions, an agent starting or finishing with nothing for him, age, or a move into Complete. By-hand tasks only by him. Ask cards keep their meaning ("I asked"), cleared when the card leaves Ask because the reviewer answered. A tick cleared this way is noted in `mine.unticked[id]` `{ why, at, cleared }`; the card carries it as `unticked` for 15 minutes and shows "unticked: <why> <time>" in red in its status line, and the sync history lists it. Ticks from before this rule got their `at` the first time the server saw them. Nothing ticks a card but him (a Review card entering Complete arrives unticked and leaves a ghost in In Progress, where he can tick it). A tick in Complete stays until the author responds or he unticks it; moving into Complete never clears one. On a tick the page also adds the card to the current hour of the Day, unless that hour already holds it. |
| `POST /api/check-result` `{ key, complete: true }` or `{ key, complete: false, reason }` | The assistant's answer to `[checked]`: complete marks it complete as `/api/complete` does; not complete removes the tick and sets `checkFailed`. |
| `POST /api/queue` `{ id }` | His queue press (see The task and its flow). Answers `{ moved: "queued" }`, or `{ moved: "preparing", session, kind }` when it started an agent. |
| `POST /api/review` `{ id }` | His review press: opens the materials in Safari, sets In Progress, and when the card's agent is live (`working`, `blocked`, `ready`, `reviewing`) delivers it `[reviewing]` with the steps listed under Messages to an agent: start the app and difit, update the summary page, open new tabs into the group, arm the difit comment monitor with the task directory's path filled in (#93 sat `ready` with neither running after his press, 2026-11-25). Answers `{ tabGroup, urls, opened, delivery }`, with `agentError` when that delivery failed; the press still counts. A queued card without materials gets `[open review]` sent to its agent instead and answers `{ delivery, askedAgent: true }`; any other card without materials is 409. |
| `POST /api/requeue` `{ id }` | His to queue press: In Progress or Blocked back to Queued, no agent started. When the card's agent is live (`working`, `blocked`, `ready`, `reviewing`) it delivers `[paused]` so the agent stops its monitor, difit servers and app (2026-11-25), answering `delivery`, with `agentError` when that failed; the move still counts. |
| `POST /api/block` `{ id, reason }` | His block press. Answers with the assistant delivery. |
| `POST /api/unblock` `{ key, why }` | The assistant unblocks when the reason no longer holds; "Unblocked: <why>" goes in his comments. |
| `POST /api/day` `{ action: "add" \| "remove" \| "title", hour, id, title }` | The old Day (no longer drawn; the Now tab replaced it). `hour` is 0 to 23. |
| `POST /api/asked` `{ id, reviewer, asked }` | He asked (or un-asked) a reviewer. Stores when. |
| `POST /api/snooze` `{ id }`, `POST /api/dismiss` `{ id }` | Hide until tomorrow, or for good. The page has no snooze button since 2026-11-25; the route stays for restoring. |
| `POST /api/order` `{ list, ids }` | The order he dragged a list into. `list` is `"<section>:<group>"` (`"Review:Now"`, `"Merge:"` for a section without groups), `"day:<hour>"` (`"day:14"`) or `"project:<name>"` (`"project:Linked Residents"`). |
| `POST /api/task` `{ project, title, explanation? }` | A by-hand task. Also how the assistant creates one. Answers with its `id`. |
| `POST /api/task-explanation` `{ id, explanation }` | Sets a by-hand task's explanation (`id` is `task:<n>`). A card with a `task.json` gets its explanation through `task-set.cjs --explanation` instead. |
| `POST /api/task-context` `{ id, file, caption, kind?, clear? }` | Adds a context picture to a by-hand task. Its directory is `~/.claude/tasks/by-hand/task-<n>/`: put the file there first (`context/<name>.png`); `file` is relative to it, and the call refuses a missing file or one outside it. `kind` is worked out from the extension when left out. `clear: true` empties the list first (alone, it just empties it). Stored on the task in `projects.json`. A card with a `task.json` uses `task-set.cjs --context` instead. |
| `POST /api/tracker` `{ name: "water" \| "stood", undo? }` | One mark, now. With `undo: true`, takes off today's last mark. Only today's marks are kept; the page fills each bar one eighth per mark toward 8 a day. |
| `POST /api/log` `{ text, from?, card?, images? }` | A Log message. `images` is a list of png, jpeg, gif or webp data urls, 10 MB each at most (the page attaches them when he pastes or drops an image in the + chat: a thumbnail with × above the box). Each is saved as `~/Documents/notes/work/log-images/<time>-<n>.<ext>`, the entry keeps their names in `images`, `/log-images/<name>` serves them, the chat bubble shows them (click to enlarge), and the `[log]` text to the assistant ends with a line `images: <absolute paths>` so it can Read them. `text` may be empty when there are images. The page shows the Log only in the + chat at the bottom right; there is no Log tab (removed 2026-11-25). `from` defaults to `me`, and a message from him is delivered to the assistant. The assistant posts with `from: "assistant"`. `card` (an id or a list) appends one line per card, `re: <card title> (<card id>)`, which the page draws as a chip linking to the card; the stored entry also gets `card: [ids]`. The assistant reads the id from either. The cards' "message" button attaches them. |
| `POST /api/comment` `{ id, text }`, `{ id, at, text }`, `{ id, at, remove: true }` | His private reminder on a card: add, edit (keeps `at`), or remove. Stored in `mine.json` under `comments[id]` as `[{ at, text }]`, oldest first, and kept until he removes it, whatever happens to the card. Never sent to any agent or posted anywhere, and never counts as activity: it does not move a card, set or clear a tick, or touch an agent. |
| `POST /api/complete` `{ id, complete }` | Marks a card complete by hand (`complete: false` removes the mark): stored in `mine.completed[id]` with its time and what the card looked like, like a tick. The card goes to its section's `Complete` group at once, standing "completed by you 1:42 pm", whatever the automatic rule says, until something newer than the mark puts it back in his hands (the events that clear a tick), which also drops the mark. The page has no button for it: he messages the assistant about the card, and the assistant calls this route. On a by-hand task (`task:<n>`) it sets the task's `done: true` and `doneAt` in `projects.json` instead (`complete: false` clears both): the task leaves Start and Not Started, counts toward its project's done total, and stays in the project's All tab with no buttons and the pill "done 1:42 pm" ("done Nov 24, 1:42 pm" on a later day); the card carries `done` (the time). |
| `POST /api/outbox-ack` `{ sessionId, id?, at?, text? }` | The assistant acknowledges a message waiting for its session in `outbox.jsonl` that it handled itself (it watches the file while his Ghostty tab is attached). Removes every entry for that `sessionId` matching `id`, `at` or `text` (give `id`; `at` and `text` are for entries queued before ids existed) and answers `{ removed }`, or 404 when nothing matches. ## Syncing with GitHub

Rebuilt 2026-11-25 after GitHub rate-limited his account for an afternoon: a sync was ~28 GraphQL calls costing ~290 points (my-prs's `search first:100` with nested `reviewThreads` alone cost 207), every 2 minutes against a 5,000-point hour, and it retried every 2 minutes through the block.

- When: a 2-minute timer syncs while `/api/state` was polled in the last 10 minutes or a background agent is busy, else every 10 minutes; the first poll after 10 quiet minutes syncs at once.
- Backoff: a run whose output says "rate limit" pauses the timer 10 minutes, doubling on each further one up to 60, or until GitHub's `retry-after` / `x-ratelimit-reset` when later (`pull-common.cjs`'s `graphql` reads the headers through `gh api -i` and prints "retry after <iso>"). A good run resets it. The pause survives a restart through the last `syncs.jsonl` line. The page draws a paused row grey, not red, and the sync arrows grey with the time in the tooltip.
- What a run asks: one call with four searches (his open valinor pull requests, `review-requested:camentree`, `team-review-requested:augusthealth/move-ins`, `reviewed-by:camentree`, all in the four repositories) and, by number, every pull request already listed plus every `kind: teammate` task's, carrying `updatedAt`, head, draft, the check rollup's `state` and his pending reviews' count. Only a pull request whose those changed, that is new, or whose details are over 30 minutes old (a resolved thread may not move `updatedAt`) is fetched in full, ten per call; the rest come from `~/Documents/notes/work/github-cache.json`, which holds the full GitHub nodes and is rewritten only by a good run (delete it to force a cold run, ~15 calls, ~180 points). Once an hour, and when the cache is missing, it also lists every open pull request in the four repositories, to catch one that asked move-ins and was reviewed by a teammate between two syncs, or a request since removed. Requesting a review does move `updatedAt`; a check finishing does not, hence the rollup state. An unchanged run is 1 call costing 1 point.
- `my-prs.cjs` and `review-queue.cjs` still run alone for the today and find-reviews skills (their old queries); `work-state.cjs` uses their `buildPulls` and `buildQueue` on the cached nodes and still writes `prs.js` and `reviews.js`.
- `settleProjects` and `noteDeparted` read a gone pull request's state over REST (`gh api repos/…/pulls/N`), not GraphQL, and project settling runs only after a good run.

## Messages to an agent

The server delivers his answers and button presses straight to the agent's session, as a new message in it: no agent watches a file. Each starts with a line saying what it is:

- `[answer] <his words>` and the options he ticked
- `[open review]`
- `[reviewing]` and the Safari tab group and urls the review press just opened, then numbered steps the agent takes in that turn: `--state reviewing`; start what is not up (the app for its branch, its difit servers); update `summary.html`'s steps ("Run the app" with its urls, "Your review" in progress); record each new url with `--material` and open only those new tabs into that group; arm a Monitor (`timeout_ms` 1800000, re-armed on expiry while `reviewing`) on `node ~/.claude/scripts/difit-comments-watch.cjs '<task directory>'`; and on each comment it reports, reply in that difit thread at once with what it will do, act by `push-and-post.md`, and reply again with the result, so none of his comments hangs (2026-11-25)
- `[paused]`, from his to queue press: stop the comment monitor, save the difit threads and stop the difit servers and the app, keep the materials, `--state ready --doing "paused, review again to resume"`; the next `[reviewing]` starts it all again (2026-11-25)
- `[comments sent]`: no longer sent by the page (the button went 2026-11-25, since the monitor picks comments up); still accepted from `/api/send`
- `[publish]` followed by the description. What it publishes depends on what is ready: `work`, open the pull request with that description; `fixes`, push and post the drafted replies. A teammate's review is no longer published this way; the agent posts it when the monitor reports his verdict comment.
- `[note] <his words>`

An idle session gets the message directly: the server stops it and resumes it with the message (`claude stop`, then `claude --bg --resume`; Claude Code 2.1.332 has no command that hands a message to a running session: re-checked 2026-11-25 in `claude --help`, `attach`, `agents`, `logs`, `respawn` help; `--bg --resume` on a running session starts a copy, and `/tmp/cc-socks/<pid>.sock` is each process's private socket with no documented protocol, so don't re-investigate until a new version's help lists one). That stop ends any terminal attached to the session, so the server never does it to a session with a `claude attach` open on it (read from the process list): a message for such a session goes through the assistant like a busy one's, and a message for the assistant itself waits in the outbox, delivery `queued until its terminal tab closes` (also when an earlier message is already waiting for it), which the page words as "the assistant will pick this up shortly": the assistant watches `outbox.jsonl` itself, handles the entry, and removes it with `POST /api/outbox-ack`; one it has not acknowledged is delivered within 30 seconds of the tab closing (his Ghostty tab on the assistant closed at every `[hourly]` and `[log]`, 2026-11-25). A busy one (mid-turn, or holding an app or a difit server as background shells) gets it through the assistant, which arrives as a cross-session message from the session named `assistant` and carries the same weight as one from him.

Every `claude` command that starts or resumes the assistant (not task agents) carries `--autocompact 300000 --settings '{"autoCompactEnabled":true}'` (2026-11-25, his ask to compact around 30% of the 1M window): his global `autoCompactEnabled: false` overrides `--autocompact` alone (`/context` in `claude -p` showed "Compact buffer", not "Autocompact buffer", until the per-session setting was added). `claude attach` takes no flags.

A Log message to the assistant arrives as `[log] <his words>`, the hourly wake as `[hourly]`, and a message to pass on as `[relay <session name>] <message>`.
